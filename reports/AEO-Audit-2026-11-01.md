# AEO Audit and Plan: pixiedigitalcreatives.com
**Date:** 1 Nov 2026 · Scope: the React + Vite codebase as committed in `4fb1a40` (GEO work included) · Method: code review, the built HTML in `dist/`, the live CMS data (`/api/cms/all`) and Google's current documentation.

> AEO (answer engine optimisation) shapes content so search engines, AI tools and voice assistants can lift it as a direct answer. Nothing here guarantees a featured snippet, an AI Overview mention or a citation in ChatGPT, Perplexity, Copilot or Gemini.

## 1. What is already in place (from the SEO and GEO work)
| Area | State |
|---|---|
| Crawlable HTML | Every page's real content is written into its HTML at build time (34 pages). |
| Pages and routes | 9 main pages, 7 service pages, 4 industry pages + index, 4 guides + blog index, 7 case studies (from the CMS). |
| Titles / descriptions | Unique per page; titles ≤ 65 characters, descriptions 70-160. |
| Headings | One H1 per page with a keyword line; H2/H3 below it. |
| Structured data | Organization, WebSite, WebPage types, BreadcrumbList, Service, BlogPosting, CreativeWork, ItemList. |
| Q&A | 4-6 questions per service page, 3 per industry page, as visible `details/summary`. |
| Crawling | robots.txt allows search, AI-answer and training crawlers; sitemap (33 URLs); llms.txt; canonical, OG and Twitter tags. |
| Images | All content images have alt text (checked in `src/`). |

## 2. Findings, by priority

### High
| # | Finding | Why it matters for answer engines |
|---|---|---|
| H1 | **Service pages answer "what" but not "who for", "why", "what do I get" or "how it applies to my industry."** Only one H2 per page is a question ("What is …?"); the rest are labels ("What's included", "Plans"). | Answer engines match questions to headings and the text right under them. Missing intents ("Who is SEO for?", "What do I get?") have nothing to match. |
| H2 | **The highest-intent price question has no answer page.** PDC publishes INR prices (Basic website ₹12,000-₹30,000 … Enterprise ₹1,50,000-₹3,00,000+), but only as plan cards on /pricing. "How much does a website cost in India?" is one of the most common pre-purchase questions. | A direct, dated, factual answer with a table is exactly what snippets and AI answers quote. |
| H3 | **No company-level Q&A.** Questions answer engines get about the brand ("Who founded Pixie Digital Creatives?", "Where is it based?", "Does it work with clients outside India?", "How do I start a project?") are answered nowhere in one place. | Brand questions are where a small studio can realistically be the answer. |
| H4 | **The founders are not described as people.** Organization schema lists them by name and title only; their bios, photos and LinkedIn/GitHub/X profiles (in the CMS and on /about) are not connected. | Clear, verifiable people behind a business are a core trust (E-E-A-T) signal. |
| H5 | **Visible Q&A has no FAQPage markup.** It was left out because Google retired FAQ rich results (May 2026). Google's documentation still says it uses FAQ structured data to understand pages, and other engines read it. | Machine-readable question/answer pairs that match the visible text. No rich result expected. |

### Medium
| # | Finding |
|---|---|
| M1 | Several example customer questions are not answered anywhere: "Which technology is best for a business website?", "How does mobile app development work?", "What is the difference between AEO and GEO?", "How can a business appear in AI-generated answers?", "How can a small business improve its online visibility?" |
| M2 | Non-build services (social media, influencer, SEO, AEO, GEO) show the website/app process (UI/UX design, full-stack development…), which does not describe how those services run. |
| M3 | The WordPress vs custom guide has no short answer at the top (the snippet-friendly part). |
| M4 | Unknown URLs return **200** with the home page (soft 404), because of the catch-all rewrite in `vercel.json`. There is also no `404.html`. Trailing-slash variants (`/about/`) are not normalised. |
| M5 | No analytics on the site (no GA4 or Vercel Analytics), so AI referral traffic and conversions **cannot be measured** yet. |
| M6 | Industry page H2s are statements ("What restaurants & cafés need from a website"), not questions. |
| M7 | Main JavaScript bundle ≈ 930 KB (≈ 2.0 s FCP/LCP on a fast connection; slower on phones). |

### Low / owner input needed
| # | Finding |
|---|---|
| L1 | Case studies are thin (21-45 words from the CMS): no challenge, approach or outcome. Only the owner can add real facts. |
| L2 | The CMS stats (95% client satisfaction, 10+ happy clients, 6+ projects, 5+ years) appear on the site and in the crawlable copy. Keep them only if you can back them up; answer engines compare sources. |
| L3 | `netlify.toml` and `public/_redirects` point to a different Render API (`pdc-api-6e15`) than `vercel.json` (`pdc-app-vm0t`). Not used on Vercel, but stale. |
| L4 | No testimonials or reviews exist on the site or in the CMS, so no Review markup is possible (and none should be invented). |

### Checked and deliberately not added
- **ProfessionalService / LocalBusiness:** these need a street address for Google's local features; PDC is remote with no public address (owner confirmed). Organization is the right type.
- **HowTo:** Google removed HowTo rich results in 2023.
- **Speakable:** beta, limited to news publishers.
- **Review / AggregateRating:** there are no genuine reviews to mark up.

## 3. Implementation plan

Rules for every change: no invented facts, results, timelines, reviews or statistics; same design system and animations; no new packages; visible text and markup stay identical.
